Gotchas & conventions

    
    
      
  • Auto-generated files -- never hand-edit: docs/index.html, docs/_assets/backend/css/cabinet-v3-style.css, docs/_assets/backend/js/cabinet-v3-*.js (all via Promote), docs/_assets/backend/js/cabinet-generated-content.js (via Rebuild Cabinet content), docs/now.md (via Rebuild Now content), docs/sitemap.md + documentation/CONTENT-INVENTORY.md (via Refresh sitemap). Every one of these gets silently overwritten by its own script the next time it runs -- edit the real source (TSVs, index.template.html, etc.) instead.
    • 
      
  • Build and Promote are deliberately two separate scripts. Build alone (landing-v3/build-static.mjs) never writes to docs/ -- it's also used on its own while iterating, without wanting every run to touch the live site. Promote is the explicit "ship this" step.
    • 
      
  • External repos assembled at deploy time are not pinned to a commit. .github/workflows/deploy.yml pulls Working with AI / Prompt Generator / Oblique Strategies / SSD Creative Coding / Swatch Fields / Tracery Bots' current default branch at build time. Pushing to one of those repos alone does not update the live site -- push a commit here too (anything, even a doc tweak), or re-run the latest "Deploy MkDocs to GitHub Pages" Action run.
    • 
      
  • Always commit TSVs and their generated output together. None of the build scripts (or this page) commit anything for you.
    • 
      
  • Port map: Now editor 5757 · Cabinet editor 5858 · this page 5959. Override with NOW_EDITOR_PORT / CABINET_EDITOR_PORT / CABINET_ADMIN_PORT if one's taken.
    • 
      
  • generate_sitemap.py needs network access (fetches raw TSVs from GitHub for all three worlds) -- if it fails, check connectivity before assuming a code problem.
